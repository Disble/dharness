# Learning Log (Vitácora)

A human-readable record of _why_ things in this repo are the way they are:
decisions taken and non-obvious problems solved, so future sessions inherit the
reasoning instead of rediscovering it.

This is a memory aid, **not** a substitute for deterministic guards. Whenever a
lesson can be enforced (linter, test, `go vet`, pre-commit gate), do that too —
this file only explains the _why_, it never replaces the _how_.

## How to append

- One lesson per line, kept to a single short sentence.
- Format: `- [YYYY-MM-DD]: text`
- Newest entries at the bottom. Never rewrite past entries; add a new line if
  something changes.

Measured against fallow 3.16.0 on a branch of 24 changed files with one clean file staged: bare `audit` reported "Audit scope: 25 changed files vs main (local main)" and exited 1 on 24 complexity findings and 8 clone groups that the staged change never touched. The 2026-08-09 measurement behind the old comment was taken in a repository with one changed file, where the branch's diff and the index are the same set — a fixture too small to distinguish the two answers, which is the part worth keeping: a measurement generalises no further than the thing that could have falsified it.
- [2026-08-14]: The fix is two flags and neither is sufficient alone, which is only visible in a fixture with a dirty working tree. `--changed-since HEAD` moves the base to the last commit, and measured, that alone restores the ratchet: a harmless edit inside a file already carrying debt passes, because against HEAD that debt is inherited rather than introduced. But it also reported a finding in a file that was only in the working tree and had never been staged — the working tree is not the index, and this gate's whole contract is the index. `--diff-stdin`, fed `git diff --cached`, is what holds that line. The recorded objection that `--changed-since` "cannot see the index" is false as measured on 3.16.0, which reported "Audit scope: 1 changed file vs HEAD" for a change that existed only there; what is true is that it needs a commit to point at, which `HasCommits` already guards.
- [2026-08-14]: The two failure modes of a diff filter are not symmetric, and only one of them is loud. Measured against fallow 3.16.0: a diff naming paths that match nothing is neither an error nor a rejection — the filter is ignored and scope falls back to whole files, so a repository-rooted path handed to a tool running in `frontend/` degrades the gate silently, which is why `StagedDiff` runs from Source with `--relative`. An *empty* diff does the opposite and worse: it admits nothing, and `audit` exits 0 over a genuinely bad staged file that the same run with a real diff exits 1 on. A green verdict from an empty scope is indistinguishable from a green verdict from a clean change, so `RunCheck` refuses an empty diff rather than passing it on.
